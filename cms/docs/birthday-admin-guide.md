# คู่มือดูแลกำแพงลูกโป่งอวยพร (สำหรับผู้ดูแลระบบ)

ทำที่หลังบ้าน เมนู **อวยพรวันเกิด** คู่มือนี้ครอบคลุมตั้งแต่เปิดงานใหม่จนถึงดูแลคำอวยพรที่เข้ามา

> คู่มือฝั่งผู้ร่วมงาน (วิธีเขียนและส่งคำอวยพร) อยู่ที่ [birthday-wish-guide.md](./birthday-wish-guide.md)

## ก่อนเริ่ม: ฐานข้อมูลต้องพร้อม

ฟีเจอร์นี้ต้องมีตารางและสิทธิ์ในฐานข้อมูลก่อน ทางที่รองรับคือ

```bash
cd cms && npm run prisma:deploy      # prisma migrate deploy
```

เซิร์ฟเวอร์ที่รัน Prisma ไม่ได้ ใช้สคริปต์สำรองแทน (idempotent รันซ้ำได้)

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f deploy/birthday-manual.sql
```

สคริปต์นี้สร้าง **ตารางกับสิทธิ์เท่านั้น ยังไม่มีงานวันเกิด** ลิงก์ `/birthday` จะขึ้นว่าไม่พบงานวันเกิด
จนกว่าจะสร้างงานในหลังบ้าน (หรือเปิดคอมเมนต์ท้ายไฟล์ SQL ข้อ 4 ที่สร้าง starter event ให้)
และต้อง deploy API ตัวใหม่ด้วย ไม่งั้น endpoint ที่เว็บไซต์เรียกจะยัง 404

## เปิดงานวันเกิดใหม่

ต้องมีสิทธิ์ `birthday.manage` (ADMIN และ SUPER_ADMIN มีอยู่แล้ว)

1. **กด "สร้างงานวันเกิด"** — ใส่ชื่องาน ชื่อเจ้าของวันเกิด และสีหลัก
   ช่อง slug เว้นว่างได้ ระบบจะสร้างจากชื่องานให้
   ถ้าตั้ง slug เป็น `birthday` ลิงก์สั้น `/birthday` จะใช้งานได้ทันที
2. **เพิ่มของขวัญอย่างน้อยหนึ่งชิ้น** — ในหน้าตั้งค่างาน ใส่ชื่อของขวัญและเลือกรูปจากคลังสื่อ
   **ข้อนี้ข้ามไม่ได้** ถ้าไม่มีของขวัญเลย ฟอร์มจะแจ้งว่ายังส่งไม่ได้และปุ่มส่งจะกดไม่ได้ทั้งหน้า
3. **เพิ่มพื้นหลังการ์ด ถ้าต้องการ** — ไม่ใส่ก็ได้ ทุกคนจะได้การ์ดพื้นเรียบตามสีลูกโป่งที่ตัวเองเลือก
4. **ตั้งสวิตช์ทั้งสามตัว**
   - *เปิดใช้งานหน้านี้บนเว็บไซต์* — ปิดแล้วลิงก์ทั้งหมดจะกลายเป็น "ไม่พบงานวันเกิดนี้"
   - *เปิดรับคำอวยพรใหม่* — ปิดแล้วยังอ่านกำแพงได้แต่เขียนไม่ได้
   - *ต้องให้ผู้ดูแลอนุมัติก่อนขึ้นกำแพง* — เปิดไว้ถ้าเป็นงานเปิดกว้าง
5. **ใส่ภาพหน้าปก แล้วคัดลอกลิงก์ไปแจกจ่าย** — ภาพหน้าปกคือรูปที่ขึ้นตอนแชร์ลิงก์ในแชต
   การ์ด "ลิงก์สำหรับผู้ร่วมงาน" ด้านบนของหน้าตั้งค่ามีปุ่มคัดลอกทั้งหน้าเขียนและหน้ากำแพงให้แล้ว

### ตรวจก่อนแจกลิงก์

- เปิดหน้าเขียนด้วยลิงก์จริง แล้วส่งคำอวยพรทดลองหนึ่งใบ
- ดูว่าใบทดลองขึ้นกำแพง (หรือขึ้นสถานะ "รออนุมัติ" ถ้าตั้งให้ตรวจก่อน)
- ลบใบทดลองทิ้งที่หน้าคำอวยพร

## ดูแลคำอวยพรที่เข้ามา

หน้า **คำอวยพร** ของแต่ละงาน ค้นหาด้วยชื่อผู้ส่งได้ และกรองตามสถานะได้สามค่า
แถบด้านบนบอกอยู่ว่างานนี้ตั้งให้ตรวจก่อนหรือขึ้นกำแพงทันที

| สถานะ / ปุ่ม | ความหมาย |
| --- | --- |
| รออนุมัติ | ส่งเข้ามาแล้ว ยังไม่แสดงบนเว็บไซต์ |
| ขึ้นกำแพงแล้ว | ลอยอยู่บนกำแพงและอ่านได้ที่หน้าคำอวยพรทั้งหมด |
| ไม่อนุมัติ | ถูกซ่อนจากเว็บไซต์ แต่ข้อมูลยังอยู่ กดอนุมัติย้อนกลับได้ |
| อนุมัติ | ปล่อยขึ้นกำแพงทันที |
| ซ่อน | เอาลงจากกำแพงโดยไม่ลบ ใช้กับใบที่ไม่เหมาะสม |
| ลบ / ลบคำอวยพรทั้งหมด | ลบถาวร กู้คืนไม่ได้ ใช้ล้างใบทดลองก่อนเปิดงานจริง |

## สิทธิ์

| สิทธิ์ | ทำอะไรได้ | บทบาทที่ได้ |
| --- | --- | --- |
| `birthday.view` | ดูงานและคำอวยพร | SUPER_ADMIN, ADMIN, EDITOR |
| `birthday.manage` | สร้างและแก้ไขงาน ของขวัญ พื้นหลัง | SUPER_ADMIN, ADMIN |
| `birthday.moderate` | อนุมัติ ซ่อน ลบคำอวยพร | SUPER_ADMIN, ADMIN |

ถ้าเมนู "อวยพรวันเกิด" ไม่โผล่ในหลังบ้านทั้งที่ API ขึ้นแล้ว แปลว่าสิทธิ์ยังไม่ถูกผูกกับบทบาท —
ส่วนที่ 2 ของ `deploy/birthday-manual.sql` ทำหน้าที่นี้ รันซ้ำได้ปลอดภัย

## ข้อจำกัดฝั่งระบบที่ควรรู้

- ผู้ร่วมงานส่งได้ไม่เกิน **6 ใบต่อนาที** ต่อหนึ่ง IP
- กำแพงดึงคำอวยพรที่อนุมัติแล้ว **300 ใบล่าสุด** เพราะทุกใบเป็นแอนิเมชันจริงบนหน้าจอ
  ใบเก่ากว่านั้นยังอ่านได้ที่หน้าคำอวยพรทั้งหมด
- รูปที่ผู้ร่วมงานอัปโหลดถูกเก็บเป็นไฟล์ต้นฉบับ ส่วนการครอปเก็บเป็นตัวเลขสามค่า (ซูม, x, y)
  ข้างกันไว้ จึงเปลี่ยนวิธีวาดลูกโป่งภายหลังได้โดยไม่เสียรูป
- ชื่อผู้ส่งจำกัด 60 ตัวอักษร คำอวยพร 300 ตัวอักษร รูปไม่เกิน 10 MB (JPG, PNG, HEIC)
